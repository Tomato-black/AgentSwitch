> 状态：待产品评审  
> 类型：页面重构（桌面端 MyGo 原生视图）  
> 关联原型：`docs/prototypes/claude-code-config-page.html`  
> 关联设计系统：`docs/audit/design-system.md`、`internal/desktop/uikit/theme.go`

> **修订说明（2026-11-07 二次设计）**  
> 用户反馈「接入页和配置页独立、来回操作太麻烦」。本版把两者合并为唯一入口 **「Agent 接入」**：Claude Code 页签内由 **接入摘要卡 + 右侧接入抽屉 + 下方 Claude Code 设置** 组成，删除原计划的独立「Claude 配置」导航。原「接入页 / 配置页」分页方案的描述保留在历史版本中，本文为实现依据。合并带来一个必要修订：受管范围从原三键扩大到接入实际写入的全部投影键（当前 13 个），否则同一页会出现两个编辑器写同一个键；该修订需在评审中确认。

## 1. 背景与用户痛点

AgentSwitch 已经能通过「接入」页把 Claude Code 指向本地网关，但 Claude Code 自身还有一整套分层 settings 体系：用户级、项目共享、项目本地、企业托管，以及 `permissions`、`env`、`statusLine`、插件开关等大量配置。今天的用户只能在「接入」页看到被投影的三个网关键，其余配置要么手改 JSON，要么完全不知道改到了哪一层。

三个具体使用时刻：

### 痛点 1：不知道哪一层在生效，排查权限要翻三个文件

周一早上，用户在项目里让 Claude Code 执行 `git push`，每次都被询问。他记得自己在项目 `.claude/settings.json` 里加过 `permissions.allow`，但 Claude Code 仍然不放过。真实原因可能是：用户级 `~/.claude/settings.json` 有一条更宽的 `deny`，或者项目本地 `settings.local.json` 覆盖了项目共享，或者企业托管策略直接拒绝。用户只能依次打开三个文件，靠自己脑内合并；而 Claude Code 的规则是 **deny → ask → allow、首个匹配即决定**，与规则写得多具体无关。没有「最终值 + 来源」视图，这个排查过程通常要十几分钟。

### 痛点 2：手改 JSON 一个尾逗号，配置静默失效

同事在聊天里发来一段 settings JSON。用户把它粘进 `~/.claude/settings.json`，多了一个尾逗号或注释。Claude Code 启动后行为像完全没生效，日志里只有一行 settings 读取失败；用户不知道是哪个文件、哪一行，也不知道当前文件已经被写坏。Claude Code 的 settings 是严格 JSON，不接受注释和尾逗号。用户需要一个会即时指出行列、保存前明确校验、写坏时能从备份恢复的编辑器。

### 痛点 3：接入后手动改模型，网关 404 或被下一次「应用」覆盖

用户刚在接入页应用了 AgentSwitch 网关。为了让某个项目用 `opus`，他手动在项目 `.claude/settings.json` 里写了 `env.ANTHROPIC_MODEL=opus`，或者在用户级写了 `model`。结果 Claude Code 请求了一个网关没有登记的逻辑模型名，返回 404；又或者他下次在接入页点「应用」，用户级里的 `ANTHROPIC_MODEL` 被重新写成网关模型，手动修改消失。用户不知道哪些键归 AgentSwitch 管、哪些键可以自己改、改完会不会被覆盖。

### 痛点 4（2026-11-07 用户反馈）：接入与设置分属两页，来回切换成本高

用户的实际任务是「把 Claude Code 接到网关，并让它按我的习惯工作」。今天他要在「接入」页改默认模型和角色映射、点应用，再切到另一个「Claude 配置」页改权限、状态栏、项目配置；改完发现模型不对，又要切回接入页。两页都写同一个 `~/.claude/settings.json`，但互相看不到对方的草稿和状态，容易覆盖、容易漏看。用户明确要求把两者合并成一个页面。

### 痛点 5（2026-11-07 用户反馈）：Skills 没有集中开关

用户的 Skills 来自内置、用户目录、项目目录和插件，数量多、名字相似。想关掉一个总是自动触发的 Skill，只能在 JSON 里写 `skillOverrides`，或者记住 `/skills` 的内部状态；从 AgentSwitch 的配置中心既看不到有哪些 Skills，也看不到某个 Skill 当前是否对模型可见、是否还能用斜杠命令调用，更无法一眼分辨「这个 Skill 归插件管，单关它无效」。

**共同根因**：Claude Code 的配置是「多文件 + 多层合并 + 少量特殊规则 + 一部分键受 scope 限制」，而 AgentSwitch 把「接入投影」和「Claude Code 自身设置」拆成了两个入口，既没有提供「看清最终结果并安全编辑」的工具，也没有把写入同一文件的两种操作放在同一上下文里。

## 2. 目标 / 非目标 / 反目标

### 2.1 目标

| 编号 | 目标 | 可验证结果 |
|---|---|---|
| G1 | 一个页面内完成接入与设置 | 用户在 Claude Code 页签内完成接入配置、应用、用户级/项目级设置编辑，不再切换页面 |
| G2 | 让「最终生效值」和「来源文件」可见 | 每个键能显示合并后的值和来源；数组能显示并集及每项来源；权限能显示 deny→ask→allow 求值顺序 |
| G3 | 安全写入 | 写前备份、原子写、只 patch 目标键、保留未知键、检测外部修改、保存后给出生效范围 |
| G4 | 同一页内接入/设置边界清晰 | 接入投影键在设置区只读并标注来源；接入抽屉与设置区不会互相覆盖；用户不需要切页 |
| G5 | 用校验挡住常见错误 | 严格 JSON、行列错误、scope 违规阻断、受管键修改阻断、疑似密钥写入项目共享时警告 |
| G6 | 降低排障成本 | 错误文案说明「发生了什么 + 下一步」；提供备份路径与恢复入口 |
| G7 | Skills 可集中开关且可解释 | 列出内置/用户/项目/插件来源的 Skills；每项显示有效状态与锁定原因；非插件 Skills 可切换开启/关闭，插件 Skills 明确指向插件开关 |

### 2.2 非目标

- 不替代 Claude Code 的 `/config`，不做全量设置百科；只覆盖常用结构化分组 + 任意键 JSON 兜底。
- 不编辑企业托管 Managed 文件；不尝试绕过 MDM / 组织策略。
- 不编辑 `~/.claude.json` 中 12 个 Global config 键（如账号、引导状态、统计缓存等），本页不读写这些键。
- 不编辑项目 `.mcp.json` 的服务定义；只提供 MCP 服务器启用/禁用开关。
- 不安装/卸载插件或市场；只切换已安装插件的启用状态。
- 不安装/卸载/编辑 Skills，不改 `SKILL.md`；只切换 `skillOverrides` 中已有 Skill 的可见性状态。
- 不尝试单独关闭插件提供的 Skill；插件 Skill 由插件开关管理（Claude Code 不允许用 `skillOverrides` 覆盖插件来源的 Skill）。
- 不管理 `--settings` 命令行传入的临时文件；只在其存在时于合并预览中说明「未检测/不参与」。
- 不做跨机器同步、云端备份、团队共享配置下发。
- 不编辑 Codex 配置；本期只做 Claude Code。未来若扩展，再决定导航命名与信息架构。

### 2.3 反目标（明确不做）

- **不做「一键优化/一键合并」**：不把多层配置静默合并写回一个文件，不替用户迁移项目级设置。
- **不隐藏问题**：scope 非法键、未知键、被覆盖的值必须显式展示，不能静默丢弃。
- **不把密钥写进项目共享文件**：检测到疑似密钥时至少警告并要求确认，优先建议改存项目本地。
- **不假装热生效**：没有把握的键一律提示「需重启 / 下次启动」，不向用户承诺即时生效。
- **不自动改 `.gitignore`**：项目本地文件是否被忽略只提示，不静默修改仓库文件。
- **不覆盖接入管理的受管键**：设置区保存时原样保留接入投影键；即使它们出现在项目文件里也不在设置区改值，需要修改时回到同页接入抽屉。

## 3. 术语与同页工作区边界

### 3.1 术语

| 术语 | 含义 |
|---|---|
| 用户级 | `~/.claude/settings.json`，对当前用户所有 Claude Code 会话生效 |
| 项目共享 | 所选项目目录下的 `.claude/settings.json`，通常随仓库提交 |
| 项目本地 | 默认位于 Git 仓库根的 `.claude/settings.local.json`，通常不提交 |
| 企业托管 | Managed policy：系统级 `managed-settings.json`、MDM plist、Windows 注册表策略、远程组织策略、父进程托管设置等 |
| 合并预览 | 按 Claude Code 优先级把多层配置合并后的只读视图，不是可保存文件 |
| 受管键 / 接入投影键 | 由同页「接入」工作区写入用户级 settings 的键集合：核心三键 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_MODEL`，以及 `ANTHROPIC_SMALL_FAST_MODEL`、`ANTHROPIC_DEFAULT_*_MODEL(_NAME)`、`CLAUDE_CODE_SUBAGENT_MODEL`。具体集合以接入实现实际写入的键为准 |
| scope 违规 | 某个键出现在 Claude Code 不允许的层级，或在当前层不生效 |

### 3.2 同一页面内的两个工作区

**合并决策（2026-11-07 用户反馈）**：接入与配置不再分成两个侧栏页面。侧栏保留一个 **「Agent 接入」** 入口；Claude Code 页签内同时提供「接入」与「Claude Code 设置」，用户不再需要来回切页。

| 维度 | 接入工作区（摘要卡 + 右侧抽屉） | 设置工作区（同页下方） |
|---|---|---|
| 解决的问题 | 让 Claude Code 走 AgentSwitch 网关 | 调整 Claude Code 自身行为（含 Skills 开关） |
| 写什么 | 用户级 `~/.claude/settings.json` 中的接入投影键 | 用户级 / 项目共享 / 项目本地中的其余 Claude Code 设置键 |
| 入口 | 页头下方接入摘要卡；点「编辑接入」打开抽屉 | 摘要卡下方「Claude Code 设置」 |
| 谁触发 | 用户点「保存并应用」/「应用接入」 | 用户点「保存设置」 |
| 是否看合并 | 否，只预览将要写入的受管键 | 是，跨层合并 + 来源 |
| 是否可改受管键 | 是，由接入配置决定 | 否，只读；点击「打开接入」回到抽屉 |
| 企业托管 | 不处理 | 只读展示来源与最终策略 |
| 项目范围 | 不写项目文件 | 可写项目共享 / 项目本地 |

**入口与文案**：

- 侧栏原有「接入」改名为 **「Agent 接入」**，作为唯一入口；删除原计划的独立「Claude 配置」导航项。
- 页面标题 **「Agent 接入」**；顶部 Agent 页签：Claude Code / Codex / Claude Desktop / 连接指南。Claude Code 页签标记「接入 + 设置」。
- Claude Code 页签内结构：**接入摘要卡 → Claude Code 设置**。摘要卡展示网关状态、当前接入配置、网关模型、是否已应用，以及「编辑接入」「应用接入」。
- 受管键行内文案从「去接入页修改」改为 **「打开接入」**，点击打开同页右侧抽屉，不再跳转。
- Codex / Claude Desktop / 连接指南仍沿用现有接入结构；本期的设置中心只合并 Claude Code。

> 命名取舍：不新增「Claude 配置」二级导航，也不把页面叫「配置」，避免与全局「设置」混淆。未来若为 Codex 增加设置中心，直接在 Codex 页签内扩展，不需要再改侧栏。

### 4.2 层级与文件模型

| 层级 | 文件 | 可写 | 说明 |
|---|---|---|---|
| 用户级 | `~/.claude/settings.json` | 是 | 默认打开；不存在时可创建 |
| 项目级 · 共享 | `<所选目录>/.claude/settings.json` | 是 | 跟会话工作目录；若 Claude Code 在子目录启动，读的是子目录的 `.claude/settings.json` |
| 项目级 · 本地 | 默认 `<Git 仓库根>/.claude/settings.local.json` | 是 | 默认跟 Git 仓库根；Windows、非 Git 仓库、家目录仓库等有例外，UI 必须显示「实际解析路径」 |
| 企业托管 | 系统 `managed-settings.json` / MDM / 远程策略等 | 否 | 只读展示；无法读取的来源标「不可见」 |

### 4.3 视图职责

> 「接入抽屉」属于接入工作区，不是 settings 视图；下表三个视图只针对下方「Claude Code 设置」。

| 视图 | 展示内容 | 可编辑 | 适合谁 |
|---|---|---|---|
| 表单 | 当前层文件中的常用键；缺失键显示「继承自下层」并提供「覆盖」 | 是 | 大多数用户 |
| JSON | 当前层文件的完整 JSON 文档 | 是（严格校验） | 高级用户、任意键兜底 |
| 合并预览 | 跨层合并后的最终值、来源、合并方式、权限求值 | 否 | 排障、确认生效结果 |
| 企业托管 | 策略来源 + 最终策略摘要 + 原始 JSON | 否 | 需要知道公司策略限制的用户 |

### 4.4 页面状态

```
接入：已应用 / 待应用 / 有未保存的接入更改 / 网关已停止 / 应用中
设置：loading → ready → dirty → saving → saved
       ready → parse-error / permission-error / conflict / empty
      managed → managed-empty / managed-partial
```

- `access.dirty`：接入抽屉里的模型/角色/配置有未保存修改。
- `access.pendingApply`：接入配置已保存但尚未写入 live 文件。
- `access.applied`：受管键与当前接入配置一致。
- `gateway stopped`：接入应用禁用，设置保存仍可用。
- `dirty`：当前 settings 文件有未保存修改。
- `saving`：写入中，保存按钮禁用并显示 Spinner。
- `saved`：显示保存结果条（生效范围 + 备份路径），直到下一次编辑。
- `conflict`：保存前发现文件被外部修改。
- `parse-error`：磁盘上的 JSON 已损坏，页面进入只读修复态。

## 5. Claude Code 配置体系（需求必须体现的事实）

### 5.1 优先级（高 → 低）

1. 企业托管 Managed policy
2. `--settings <file-or-json>` 命令行
3. 项目本地 `.claude/settings.local.json`
4. 项目共享 `.claude/settings.json`
5. 用户级 `~/.claude/settings.json`

设置区可以确定并展示 1、3、4、5；第 2 项只有在 AgentSwitch 能检测到 Claude Code 启动参数时才展示，否则在合并预览中标注「未检测到；仅当 Claude Code 以 --settings 启动时生效」。

### 5.2 合并规则

| 类型 | 键 | 合并方式 |
|---|---|---|
| 标量 / 整对象 | `model`、`effortLevel`、`permissions.defaultMode`、`statusLine` 等 | 最高层取值；低层值被覆盖（`statusLine` 按整对象覆盖） |
| 数组并集 | `permissions.allow`、`permissions.ask`、`permissions.deny`、`permissions.additionalDirectories` 等 | 跨层并集、去重；每项保留来源 |
| 环境变量 | `env` | **逐变量**取最高层，不是整对象替换 |
| 钩子 | `hooks` | 跨层累加；预览按层展示，不承诺执行顺序 |
| 插件开关 | `enabledPlugins` | 按 `plugin@marketplace` 逐键取最高层；高层 `false` 可以覆盖低层 `true` |
| Skills 覆盖 | `skillOverrides` | 按 Skill 名逐键；有效状态 = 锁定值（托管/flag/作者/插件）否则 `local > project > user > on` |
| 整值替换例外 | `fallbackModel`、`modelPicker`、`availableModels`、`modelSettings` | 取最高层的整个值，**不合并、不并集**（`fallbackModel` 虽然仍是数组，也不做并集） |

特殊说明：

- `modelSettings` 按整值替换处理；其内部细节不在本期表单中展开。
- `enabledPlugins` 的优先级是 user < project < local < flag < policy；项目本地写 `false` 可以关掉项目共享启用的插件。
- `skillOverrides` 的取值是 `on` / `name-only` / `user-invocable-only` / `off`；缺省等价 `on`。**插件来源的 Skill 不能由 `skillOverrides` 单独覆盖**，必须通过 `enabledPlugins` 或 `/plugin`；技能作者声明 `disable-model-invocation` 时也不能被提高为 `on`。
- `autoMemoryDirectory` 如果写在项目共享 `.claude/settings.json` 中，Claude Code 会出于安全考虑忽略；UI 需要提示并建议放到用户级或项目本地。

### 5.3 权限求值

1. 先看 `deny`，再看 `ask`，最后看 `allow`。
2. 首个匹配的规则决定结果，与规则写得多具体无关。
3. 任意层的 `deny` 都压过任意层的 `allow`；项目级 `allow` 不能覆盖用户级或托管层的 `deny`。
4. 预览需要展示：三组规则的数量、每项来源、求值顺序说明；不要求本期做完整的工具调用模拟器（可作为 P1）。

### 5.4 scope 限制（关键）

- **30 个键只能出现在用户级或 Managed**，例如 `autoMode`、`modelPicker`、`sandbox.allowAppleEvents`。这些键写在项目共享或项目本地不会生效。
- **4 个键不能进项目共享**：`skipDangerousModePermissionPrompt`、`syncClaudeAiPlugins`、`syncClaudeAiSkills`、`useAutoModeDuringPlan`。
- `skipDangerousModePermissionPrompt` 是**危险模式确认的预授权记录**，不是权限模式本身：`true` 表示用户已接受 Bypass Permissions 模式的免责声明，进入该模式时不再弹出确认；它不会自动开启 Bypass，也不改变当前 `permissions.defaultMode`。合并语义为 **任一层 `true` 即 `true`（OR）**，`false` 不能覆盖其他层的 `true`。
- `worktree.location` **仅用户级**（桌面 SSH 场景）。
- **12 个 Global config 键只能写 `~/.claude.json`**，不在本页范围；本页不得读写这些键。
- `permissions.defaultMode` 的 `auto` / `bypassPermissions` **从项目级设置不生效**；项目级写了也要在 UI 标注「不生效」，合并预览应回落到较低层的有效值。
- 完整键清单由实现期的「键注册表」维护；本文给出类别、示例与 UI 规则。注册表必须能回答四个问题：键路径、类型/枚举、允许的层级、合并方式与生效方式。

### 5.5 文件与 JSON 事实

- settings 文件是**严格 JSON**：不接受注释、尾逗号、单引号。
- 项目共享文件跟会话工作目录；项目本地文件默认跟 Git 仓库根，存在平台/仓库形态例外。
- Unknown keys：Claude Code 可能忽略；设置区必须保留，不因保存而删除。
- 写入必须是原子写；写前备份；只改目标键，保留未知键与格式之外的语义。

### 5.6 热生效

- 多数键热重载。
- `model`、`effortLevel` 等需要重启 Claude Code 会话。
- 移除 `blockReadsOutsideWorkingDirectories` 等需要下次启动。
- 项目级改动默认按「下次启动 / 新会话」提示，除非实现期实测确认可热加载。
- 保存结果必须三选一：**已热生效 / 需重启 / 下次启动**，并列出触发该结论的键。

## 6. 逐模块交互说明

### 6.1 页面进入与全局行为

1. 点击侧栏 **「Agent 接入」** 进入；默认 Agent 页签=Claude Code；设置区默认层级=用户级、视图=表单。
2. Claude Code 页签的固定结构：**接入摘要卡 → Claude Code 设置**。接入抽屉默认关闭，点「编辑接入」打开。
3. 进入时并行读取：
   - 网关实际状态与地址（来自 Gateway.Status()，不是按钮状态）；
   - 接入配置列表、当前配置、上次保存/应用时间；
   - 用户级 settings；
   - `~/.claude.json` 的 `projects`；
   - 当前记忆的项目（若存在）的共享/本地文件；
   - 企业托管来源（能读到的）；
   - 插件清单、项目 `.mcp.json` 服务器名、AgentSwitch 逻辑模型列表。
4. 加载中显示骨架/加载行；超过 300ms 的操作必须有进行中反馈。
5. 页头「保存设置」只在设置区可写层、存在未保存修改、JSON 合法、无阻断错误时可用。
6. **主操作规则**：
   - 设置区有未保存修改时，页头「保存设置」是唯一橙色胶囊主操作；接入卡片的应用按钮是软底次操作。
   - 接入抽屉打开时，抽屉底部「保存并应用」是该视图的橙色主操作；遮罩下的设置页不可操作。
   - 企业托管层级不显示接入主操作以外的编辑入口。
7. **同页协调**：接入与设置都会写用户级 `settings.json`，但写的是不同键。应用接入前若设置区有未保存修改，必须先保存或放弃设置；设置保存不修改受管键。两者在 AgentSwitch 内串行写同一文件。
8. Codex / Claude Desktop / 连接指南页签仍沿用现有接入结构；本期的合并只针对 Claude Code。切换到这些页签时关闭接入抽屉并保留 Claude Code 的未保存草稿。

### 6.2 接入摘要卡与接入抽屉

#### 6.2.1 接入摘要卡

- 始终位于 Claude Code 页签顶部，不需要展开。
- 第一行：接入图标 +「Claude Code 接入」+ 状态徽章：
  - `已应用`（ok）：受管键与当前接入配置一致；
  - `待应用`（warn）：接入配置已保存但未写入 live 文件；
  - `有未保存的接入更改`（warn）：抽屉里有未保存的模型/角色/配置修改；
  - `网关已停止`（danger）：应用按钮禁用。
- 第二行：网关 LED + 运行中/已停止 + 等宽地址 + 当前接入配置名 + 网关模型（含 `[1M]` 徽章）+ 最后应用时间。
- 说明文案：「接入只写受管键（Base URL、令牌、主模型、SMALL_FAST 与角色映射，共 N 个）；权限、状态栏、项目配置在下方「Claude Code 设置」中编辑。」
- 操作：
  - **编辑接入**（次）：打开右侧抽屉；
  - **应用接入**（软底 act）：仅在有未保存接入修改或待应用时出现；
  - **重新应用**（次）：已应用且无修改时出现；
  - 网关停止时应用按钮禁用，旁注「先启动网关」。
- 卡片本身不写文件；只有抽屉的「保存并应用」或卡片「应用接入」触发写入。

#### 6.2.2 接入抽屉

- 右侧抽屉，宽 560（小窗口 94vw），带遮罩；Esc 关闭；遮罩点击关闭；关闭时保留未保存草稿并在摘要卡显示「有未保存的接入更改」。
- 内容：
  1. 接入配置选择（默认配置 / 其他已保存配置）+「新建」；
  2. 全局配置折叠区：展示会合并进所有接入配置的键（如 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`、`API_TIMEOUT_MS`）；本期只读展示，不在此编辑（如后续支持，再放开）；
  3. 默认逻辑模型下拉 +「1M 上下文声明」勾选；
  4. 角色映射：Sonnet / Opus / Fable / Haiku / Subagent，每行一个模型下拉，支持「跟随主模型」；
  5. 「将写入的受管键」只读预览：`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`（遮蔽）、`ANTHROPIC_MODEL`（含 1M 后缀）、`ANTHROPIC_SMALL_FAST_MODEL`、`ANTHROPIC_DEFAULT_*_MODEL(_NAME)`、`CLAUDE_CODE_SUBAGENT_MODEL`；显示共 N 个键；
  6. 提示：应用后写入用户级 `~/.claude/settings.json`；写前备份，只改这些键，其余设置原样保留；
  7. 网关停止警告。
- 底部操作：
  - **关闭**（文本/次）：保留草稿，关闭抽屉；
  - **仅保存**（次）：保存接入配置到 AgentSwitch 数据库，不写 live 文件；摘要卡变「待应用」；
  - **保存并应用**（主，橙色胶囊）：保存并写入 live 文件；网关停止时禁用。
- 字段变更即标记 `access.dirty`，摘要卡状态实时变「有未保存的接入更改」；预览随模型/角色/1M 即时更新。
- 抽屉不编辑完整 settings；不展示权限、状态栏、项目配置。需要这些时关闭抽屉，在下方设置区编辑。

#### 6.2.3 应用接入

1. 点「保存并应用」或摘要卡「应用接入」：
   - 网关停止 → 按钮禁用并提示；
   - 设置区 dirty → 弹「先处理未保存的 Claude Code 设置」：
     - 主按钮（末位、默认聚焦）：**去保存设置**（关闭抽屉、聚焦设置保存按钮）；
     - 次按钮：**取消**；
     - 不提供「直接覆盖设置」的危险默认路径。
2. 设置区 clean → 弹确认框：
   - 目标文件 `~/.claude/settings.json`；
   - 接入配置名、网关模型（含 1M）、受管键数量、备份路径；
   - 生效范围：**需重启 Claude Code**（环境变量与模型映射变更）；
   - 按钮：取消 / 应用（主）。
3. 应用执行：
   - 写前备份；只 patch 受管键；保留其余键；原子写；
   - 更新接入配置的 `lastApplied`；`access.dirty=false`、`access.applied=true`；
   - 关闭抽屉/确认框；刷新设置区文件内容与合并预览；
   - Toast「接入已应用，受管键已更新」。
4. 应用失败：保留抽屉与设置草稿；错误说明原因（权限/备份/写入/网关停止）与下一步；不部分写入。
5. 应用后如果设置区当前是用户级表单，受管键行立即显示新值；如果是项目级，继承区与合并预览刷新；如果 JSON 视图有干净草稿，重新加载为最新文档。

#### 6.2.4 仅保存

- 只写 AgentSwitch 数据库，不写 live 文件。
- `access.dirty=false`、`access.applied=false`，摘要卡「待应用」。
- 设置区不受影响；受管键仍是旧值，合并预览仍显示旧值。
- 可在之后从摘要卡或抽屉再次应用。

#### 6.2.5 接入与设置的冲突规则

- 接入应用前必须保证设置区 clean；设置区 dirty 时只允许「去保存设置」或取消。
- 设置保存只改非受管键，不触碰受管键；即使接入有未保存修改，也可以保存设置。
- 同一文件的外部修改（其他编辑器、接入应用）在设置保存前重新读取比对；冲突走 6.11 的冲突对话框。
- 接入应用后，设置区的文件状态变为「已保存」，上次保存时间更新为应用时间；不把接入写入误标为设置保存。

### 6.3 层级切换

- 三个分段：**用户级 / 项目级 / 企业托管（只读）**。
- 用户级与项目级显示文件是否存在的小圆点；企业托管显示锁图标。
- 切换前若当前文件有未保存修改，弹「放弃未保存的修改？」：
  - 主按钮（末位、默认聚焦）：**继续编辑**；
  - 次按钮：**放弃修改**（danger 软底，不默认聚焦）。
- 切到项目级：
  - 若已有上次选择项目，直接打开该项目；
  - 否则显示「选择一个项目」空态，项目选择器获得焦点。
- 切到企业托管：隐藏表单/JSON 视图切换，只显示只读内容；保存按钮隐藏或禁用并说明「托管配置只读」。

### 6.4 项目选择

- 数据源：`~/.claude.json` 的 `projects` 键（项目绝对路径列表）。
- 排序：优先按最近一次会话文件 mtime；无法取得时按项目目录 mtime；再无法取得时按名称。UI 标注「最近使用」或「按名称」。
- 下拉项显示：项目名（目录 basename）、路径（等宽、单行省略）、徽章（共享文件存在 / 本地文件存在 / 目录不存在）。
- 支持搜索过滤；项目多时显示搜索框。
- 「选择目录…」打开系统目录选择器；选中后校验：
  - 必须是存在的目录；
  - 不要求是 Claude 项目；若不是，提示「该目录还没有 .claude 配置，保存时会创建」；
  - 若目录不可读/无权限，显示错误并保留原选择。
- 记住上次项目路径（存 AgentSwitch 自身设置，不写 Claude 文件）；下次进入项目级自动恢复。
- 项目上下文条：
  - 共享子页签：`.claude/settings.json`；
  - 本地子页签：`.claude/settings.local.json`；
  - 下方等宽显示**实际解析路径**；
  - 本地路径与所选目录不一致时显示说明：「本地配置默认跟随 Git 仓库根；当前解析到 `<git root>`」；
  - 若 Claude Code 可能在子目录启动，显示提示：「共享文件跟会话工作目录；若在子目录启动，读取的是子目录的 .claude/settings.json」。
- 没有项目 / 目录不存在：空态 + 重新选择；不自动创建目录。

### 6.5 视图切换

- 表单 / JSON / 合并预览三个页签，使用框架 Tabs（方向键、Home/End）。
- 切到 JSON：
  - 若表单有未保存修改，先把当前文档序列化到 JSON 草稿，保证不丢；
  - JSON 草稿按当前文件独立保存，切换文件时清空。
- 切到合并预览：
  - 预览基于**已保存内容**；若当前有未保存修改，顶部显示提示「预览不包含当前草稿，保存后更新」；
  - 不因切到预览而丢草稿。
- JSON 非法时切回表单：阻止并提示「先修复 JSON 错误，或放弃修改」；提供「放弃修改」入口。
- 企业托管层级不显示这三个页签。

### 6.6 表单视图

表单只展示**当前层文件里存在的键**；不存在的键以「继承自下层」行出现，并给出「覆盖」按钮。这样用户既能看到继承关系，又不会误以为当前层已经写了值。

#### 6.6.1 模型与响应

| 字段 | 键 | 控件 | 校验与说明 |
|---|---|---|---|
| 主模型 | `model` | 文本输入 + 建议下拉（当前 Claude 别名、AgentSwitch 逻辑模型） | 非空（若设置）；≤128 字符；若与接入受管 `ANTHROPIC_MODEL` 不一致，显示 warn：「网关当前模型为 my-code；填写其他名称需先在逻辑模型页登记，否则可能 404」；提供「跟随网关」快捷值 |
| 回退模型 | `fallbackModel` | 有序数组编辑器：chip + 添加/删除/上移/下移 | 每项非空；去重警告；整值替换，不跨层并集；不填=继承 |
| 推理强度 | `effortLevel` | 下拉：继承 / low / medium / high / xhigh | 枚举；需重启；项目层可写但保存后提示重启 |
| 思考开关 | `alwaysThinkingEnabled` | 三态：继承 / 开启 / 关闭 | 缺省或 true=开启；false=关闭；需重启 |
| 高级模型键 | `modelPicker`、`availableModels`、`modelSettings`、`maxEffortLevel` | 不放进表单，显示说明 + 「去 JSON 编辑」 | `modelPicker` 仅用户级/命令行/托管可写；`availableModels`/`modelSettings` 整值替换；`maxEffortLevel` 跨层取最低值，属高级项 |

交互细节：

- `model` 输入框下方显示当前有效模型来源（用户级/项目本地等）。
- 若用户填写了网关未登记的名称，保存不阻断，但保存确认框里再次提示风险。
- 若当前层没有 `model`，显示「继承：sonnet（用户级）」+「覆盖」。
- `fallbackModel` 的 chip 上显示序号，明确「按顺序尝试」。

#### 6.6.2 环境变量

- 表格列：变量名（等宽）、值（默认遮蔽敏感值）、来源/状态、操作。
- **接入投影键在设置区的所有层级都只读**。集合以接入实现实际写入的键为准，当前为：
  - 核心三键：`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_MODEL`；
  - `ANTHROPIC_SMALL_FAST_MODEL`；
  - 角色映射：`ANTHROPIC_DEFAULT_SONNET_MODEL(_NAME)`、`ANTHROPIC_DEFAULT_OPUS_MODEL(_NAME)`、`ANTHROPIC_DEFAULT_FABLE_MODEL(_NAME)`、`ANTHROPIC_DEFAULT_HAIKU_MODEL(_NAME)`；
  - `CLAUDE_CODE_SUBAGENT_MODEL`。
- 行内显示锁图标 + 徽章「接入投影」+「打开接入」；点击打开同页右侧接入抽屉。
- 为避免长表：核心三键始终展示；其余投影键默认折叠为「展开接入投影的其他 N 个键」，展开后只读。
- `ANTHROPIC_MODEL` 若带 `[1M]` 后缀，显示「1M 上下文声明」徽章；设置区不得改模型名或后缀。
- 不在接入写入集合内的其他 `ANTHROPIC_*` 键仍可编辑；若键名看起来像接入投影键，显示提示「请确认是否应由接入管理」。
- 敏感值规则：键名匹配 `TOKEN|KEY|SECRET|PASSWORD|AUTH` 时默认遮蔽；提供逐行「显示/隐藏」；复制走剪贴板并 Toast；复制不写日志。
- 新增变量：变量名正则 `^[A-Za-z_][A-Za-z0-9_]*$`；当前层内不允许重复；值为空时 warn；`env` 逐变量合并，表单下方显示「当前层 N 项，合并后 M 项」链接到合并预览。
- 当前层没有某个变量时，在「继承自下层」区展示（只读），并提供「在本层覆盖」；接入投影键在继承区只显示核心三键 + 「其余 N 个接入投影键（只读）」，避免刷屏。
- 项目层出现接入投影键时显示 warn：项目级值会覆盖用户级接入，可能导致鉴权/路由异常；设置区不改这些键，建议删除项目层覆盖后在接入抽屉重新应用。

#### 6.6.3 权限

- `permissions.defaultMode` 下拉：
  - 继承 / `default` / `acceptEdits` / `plan` / `auto` / `bypassPermissions`（以键注册表枚举为准）。
  - 项目级下 `auto` 与 `bypassPermissions` 置灰，提示「从项目级设置不生效」；
  - 若文件里已经写了这两个值，显示 warn：「当前项目层值不生效，实际使用较低层的 `<值>`」。
- 三组规则：`deny`（红/危险语义）、`ask`（琥珀/警示语义）、`allow`（绿/健康语义）。
  - 每组显示计数与 chip 列表；chip 可删除；「添加规则」展开输入。
  - 规则校验：非空；建议格式 `Tool` 或 `Tool(specifier)`；未知工具名 warn；同层重复 warn。
  - 说明文案固定展示：「求值顺序 deny → ask → allow；首个匹配决定；deny 任意层压过 allow 任意层；与规则具体程度无关」。
- `permissions.additionalDirectories`：
  - chip 列表；新增时校验为绝对路径（支持 `~/`）；
  - 路径不存在 warn；
  - 数组跨层并集，当前层只编辑自己的项。
- 当前层没有某组规则时，显示「继承自下层」的只读 chip 和来源；不把继承项写进当前文件。
- 「试算工具调用」为 P1，不在本期验收范围。

#### 6.6.3.1 危险模式确认（`skipDangerousModePermissionPrompt`）

- 三态控件：**继承 / 跳过确认（true）/ 显示确认（false）**；默认值为 **true**（AgentSwitch 产品默认，需在文案中与 Claude Code 自身的缺省 `false` 区分）。
- 用户级新建配置默认写入 `true`；已有用户级文件缺少该键时，表单按默认 `true` 展示并标注「AgentSwitch 默认，保存后写入」，用户可改为 `false` 或继承（不写入）。
- 语义：`true` 表示已接受 Bypass Permissions 模式免责声明，以该模式启动时不再弹确认；**不会自动进入 Bypass，也不改变默认权限模式**。
- 写入范围：用户级、项目本地可写；**项目共享禁用**（灰显 +「不能写入项目共享」）；企业托管只读。JSON 中在项目共享手写该键时按 scope 错误阻断。
- 合并：**任一层 `true` 即 `true`（OR）**；`false` 只有在该键所有出现层均为 `false` 时才是最终值。合并预览必须显示「OR 合并」并列出每层贡献。
- 生效：下次启动 Claude Code 或下次请求进入 Bypass 模式时生效；不承诺热生效。
- 安全提示：默认 `true` 是预授权，关闭后下次进入 Bypass 模式会重新弹出确认；UI 必须保留「默认开启」标识，不得隐藏该键或让用户误以为它只是普通开关。

#### 6.6.4 状态栏

- `statusLine` 对象：
  - 类型固定 `command`（本期只支持 command）；
  - 命令（等宽，必填）；
  - `padding`（整数 ≥0，默认 0）；
  - `refreshInterval`（整数 ≥1 秒，可选）；
  - `hideVimModeIndicator`（三态开关）。
- 当前层没有 `statusLine`：显示继承摘要（命令 + 来源）+「在本层覆盖」。
- 校验：命令非空；长度上限（建议 4096）；若看起来是本地路径且文件不存在，warn；不阻断保存。
- 安全提示：「命令会由 Claude Code 在本机执行；设置区不会主动运行它」。P0 不提供「试运行」；P1 可加，但必须二次确认、超时、只读输出。
- `statusLine` 按最高层整对象覆盖；预览中标注「整值覆盖」。

#### 6.6.5 MCP 与插件开关

- 插件：
  - 列出 `enabledPlugins` 的 `plugin@marketplace` 项；
  - 每个插件三态：继承 / 开启 / 关闭（项目本地 false 可覆盖项目共享 true）；
  - 显示插件是否已安装（读本地插件清单）；未安装的插件 warn，但允许保存开关；
  - 只做启用/禁用，不提供安装/卸载/市场操作。
- MCP：
  - `enableAllProjectMcpServers` 三态开关；
  - `enabledMcpjsonServers` / `disabledMcpjsonServers` 两个 chip 列表；
  - 显示项目 `.mcp.json` 中检测到的服务器名，便于选择；
  - 同名同时出现在 enabled 与 disabled 时 warn；
  - 不编辑 `.mcp.json` 服务定义。
- 用户级额外显示 `syncClaudeAiPlugins`、`syncClaudeAiSkills` 开关（这两个键不能进项目共享）；项目共享下隐藏或置灰并说明。

#### 6.6.6 Skills（`skillOverrides`）

- 独立卡片「Skills」，位于「MCP 与插件」之后；标题旁显示计数：开启 N / 关闭 M / 其他状态 K / 插件管理 L。
- 列表来源与识别：
  - 内置 Skills（Claude Code bundled）；
  - 用户级 `~/.claude/skills/*/SKILL.md`；
  - 项目级 `.claude/skills/*/SKILL.md`；
  - 已安装插件携带的 Skills；
  - 已存在于 `skillOverrides` 但本次未识别到的 Skill 名，作为「未识别」项保留，不静默删除。
- 每一行展示：Skill 名（等宽，插件用 `plugin:skill`）、来源徽章（内置/用户/项目/插件）、简短描述（可截断）、**有效状态**、锁定原因（如有）、当前层的覆盖控件。
- 状态枚举与含义：
  - `on`（开启）：列出名称与描述，模型可自动触发，也可 `/name`；
  - `name-only`（仅名称）：只列名称、不加载描述，模型不能自动触发；
  - `user-invocable-only`（仅手动）：对模型隐藏，仍可 `/name`；
  - `off`（关闭）：对模型和斜杠命令都隐藏；
  - 继承：当前层不写该键，沿用低层或默认 `on`。
- 控件：每行一个下拉，选项「继承（未设置）/ 开启 / 仅名称 / 仅手动调用 / 关闭」；默认值为 `on`（不写键即开启）。「继承」会删除当前层该 Skill 的 override；若删除后 `skillOverrides` 为空对象，则一并删除该键。
- 锁定规则：
  - 插件来源的 Skill：控件禁用，显示「由插件管理」+ 指向「MCP 与插件」卡片的插件开关；不写 `skillOverrides`；
  - 托管策略或 flag 指定了某个 Skill：该行禁用并显示「托管策略锁定」，其他 Skill 仍可编辑；
  - 技能作者声明 `disable-model-invocation`：最高只能到 `user-invocable-only`，不能设为 `on`；
  - `__proto__` 等无法存入 JSON 对象的名称：不提供控件，提示重命名。
- 合并与来源：按 Skill 名逐键合并；有效状态取 policy/flag 锁定值，否则项目本地 > 项目共享 > 用户级 > `on`。每行显示「生效：关闭 · 项目本地」这类来源说明；合并预览新增 `skillOverrides.<name>` 行。合格名（`plugin:skill`）与未限定名的查找细节以 Claude Code 实际解析为准，UI 只展示解析后的有效状态与来源，不自行重排优先级。
- 插件关闭时：该插件携带的 Skills 显示「插件已关闭」，不重复提供单 Skill 开关。
- 项目共享层：允许写 `skillOverrides`，但关闭 Skill 会影响所有协作者；控件旁显示 warn「将写入项目共享并可能被提交」。
- 校验：`skillOverrides` 必须是对象，值为四个枚举之一；非法值在 JSON 视图中按错误阻断，未知 Skill 名只警告不阻断。
- 生效：保存后新会话生效；卡片提供「在 `/skills` 中查看」说明，不假装当前会话立即刷新。
- 无法读取 Skill 列表时：显示错误与原因，保留 JSON 视图作为兜底；不显示空白列表冒充「没有 Skills」。

#### 6.6.7 记忆与上下文

- `autoCompactEnabled`：三态开关；说明「上下文将满时自动压缩」。
- `autoMemoryEnabled`：三态开关；说明「允许 Claude 读取/写入项目自动记忆目录」。
- `cleanupPeriodDays`：整数 ≥1（默认 30）；本期只提供用户级编辑入口（托管策略只读），项目级显示只读说明；项目层是否允许该键以键注册表与当前 Claude Code 版本复核为准。
- `autoCompactWindow`、`autoMemoryDirectory` 等高级键：本期只走 JSON；`autoMemoryDirectory` 在项目共享中会被 Claude Code 忽略，UI 需警告。
- 所有数值输入保存时做整数校验；失焦/保存时显示错误。

### 6.7 JSON 视图

- 展示当前层文件的完整 JSON，等宽字体、行号、可滚动。
- 编辑行为：
  - 输入后 300ms 防抖解析；
  - 严格 JSON；错误显示「第 X 行第 Y 列 + 原因」，保存禁用；
  - 合法时实时更新内部文档并标记 dirty，但不自动保存；
  - 「格式化」按钮：按 2 空格缩进重排；
  - 「重置」按钮：恢复到上次保存内容，需确认；
  - 「校验」按钮：执行解析 + scope 校验 + 受管键校验，结果内联展示。
- 顶部固定提示：「严格 JSON：不支持注释与尾逗号；此视图可能包含明文密钥，请勿截图或分享。」
- 受管键 / 接入投影键：
  - 所有接入投影键在编辑器中仍显示，但有锁标记说明；
  - 若值与打开时不同，保存阻断并提示「`ANTHROPIC_AUTH_TOKEN` 由本页「接入」管理；打开接入抽屉修改」；
  - 若文件里缺少核心受管键，显示 warn「受管键缺失，接入可能未应用；打开接入重新应用」。
- scope 校验：
  - 用户级不允许写 Managed-only 键；项目层不允许写用户级专属键；项目共享不允许写 4 个禁止键；
  - 对**本次新引入/修改**的违规键阻断保存；
  - 对文件里已存在、本次未改动的违规键只警告并原样保留，避免用户被历史问题困住；
  - 违规项可点击定位到 JSON 行。
- 未知键：允许保存，显示 info「Claude Code 可能忽略此键」。
- 文件超过 1 MiB：拒绝页内编辑，提示用外部编辑器；避免卡顿。
- 文件是符号链接：显示解析后的真实路径，写入真实目标，不替换链接。
- 文件权限不可写：只读展示 + 错误说明 + 重试。

#### 6.8.2 权限求值卡

- 三段式：`1 deny` → `2 ask` → `3 allow`，首个匹配决定。
- 每段显示规则数量与来源分布。

#### 6.8.3 键行

每个键一行：

### 6.9 保存与生效提示

#### 6.9.1 保存前

1. 校验 JSON（JSON 视图）或表单字段。
2. 校验 scope 与受管键。
3. 重新读取磁盘文件，比较 mtime + 内容 hash：
   - 未变化：继续；
   - 已变化：弹冲突对话框（见 6.11）。
4. 计算变更键列表（leaf path），用于确认框与生效判断。
5. 若项目共享文件中检测到疑似密钥：警告并要求确认，提供「改存到项目本地」的说明。
6. 若目标文件不存在：确认「将创建 `<path>`」；项目共享额外提示「此文件通常会被提交到 Git」。
7. 打开保存确认框：
   - 标题「保存到用户级配置？」/「保存到项目共享配置？」；
   - 路径（等宽）；
   - 变更键 chip（最多展示 8 个，其余「等 N 个」）；
   - 备份路径；
   - 生效范围徽章：已热生效 / 需重启 / 下次启动；
   - 项目共享的密钥/提交警告；
   - 按钮：取消（次）/ 保存（主，末位）。

#### 6.9.2 写入

- 备份当前文件到 `~/.agentswitch/backups/claude-settings/<timestamp>-<hash>-<filename>`；每个文件保留最近 10 份；备份失败则**不写入**。
- 原子写：同目录临时文件 → fsync → rename；保留原文件 mode；新文件建议 0600。
- 表单保存：只 patch 变更键；删除键 = 从当前层移除；未知键原样保留。
- JSON 保存：写入解析后的完整文档；未知键原样保留；2 空格缩进 + 末尾换行。
- 写入期间保存按钮禁用 + Spinner + 「正在写入…」；不得阻塞渲染线程。
- 写入成功后更新基线、清除 dirty、刷新文件状态与合并预览。

#### 6.9.3 保存后

- 页头下方出现结果条：
  - `success`：**已热生效**；「已写入 `<path>`；备份：`<path>`」；
  - `warning`：**需重启 Claude Code** 或 **下次启动生效**；说明触发键；
  - 提供「查看备份」「撤销本次保存」（P1，可先只做查看备份）。
- 同时 Toast「已保存」。
- 结果条持续到下一次编辑或手动关闭。
- 若写入后发现文件被外部修改，提示「文件已变化，请刷新后确认」。
- 生效判断：
  - 变更包含 `model`、`effortLevel`、`alwaysThinkingEnabled` 等重启键 → 需重启；
  - 移除 `blockReadsOutsideWorkingDirectories` → 下次启动；
  - 项目级文件 → 默认下次启动 / 新会话；
  - 其余 → 已热生效；
  - 未知键 → 下次启动（保守）。

### 6.10 错误、空态、加载态

| 场景 | 展示 | 主操作 | 次操作 |
|---|---|---|---|
| 用户级文件不存在 | 空态「还没有用户级配置」+ 说明 | 创建 settings.json | 查看示例 |
| 项目未选择 | 空态「选择一个项目」 | 选择项目 | 选择目录 |
| 项目目录不存在 | 错误「项目目录不存在或不可访问」 | 重新选择 | 从列表移除 |
| 项目共享/本地文件不存在 | 空态「该项目还没有共享/本地配置」 | 创建文件 | 切换另一层 |
| 企业托管无来源 | 空态「未检测到企业托管策略」 | 刷新 | 了解托管策略 |
| 托管来源不可读 | warn 行 + 路径 + 原因 | 重试 | 复制路径 |
| 磁盘 JSON 损坏 | 只读错误卡：文件、行列、原因 | 从备份恢复 | 用外部编辑器打开 / 用空配置重建（危险，二次确认） |
| 文件权限不足 | 错误「无法写入：权限不足」 | 重试 | 复制路径 / 查看帮助 |
| 备份失败 | 错误「备份失败，已取消写入」 | 重试 | 复制路径 |
| 保存冲突 | 对话框「文件已被其他程序修改」 | 取消（默认） | 重新加载 / 覆盖写入（危险软底） |
| scope 违规 | 错误列表 + 定位链接 | 去修复 | 放弃本次修改 |
| 受管键被改 | 错误「由本页接入管理」 | 打开接入 | 还原该键 |
| JSON 语法错误 | 行内红色错误 + 行号 | 修复 | 重置 |
| 超过 1 MiB | 警告 + 只读 | 用外部编辑器打开 | 复制路径 |

空态规则：每屏最多一个主操作；空态文案指出下一步在哪；列表非空但搜索无结果时用「无匹配结果 + 清除搜索」，不与首次空态混用。

### 6.11 脏状态与冲突

- 脏状态触发：表单任何输入变化；JSON 合法解析后的变化；数组增删；受管键意外变化（受管键变化应阻断而不是进入普通 dirty）。
- 切层级、切项目、切共享/本地、离开页面：脏检查。
- 脏检查对话框：
  - 标题「放弃未保存的修改？」；
  - 正文说明当前文件与修改数量；
  - 主按钮（末位、默认聚焦）「继续编辑」；
  - 次按钮「放弃修改」（danger 软底，不默认聚焦）。
- 保存冲突对话框：
  - 标题「文件已被其他程序修改」；
  - 说明「磁盘上的内容与打开时不同。重新加载会丢失当前修改；覆盖写入会覆盖外部修改。」；
  - 按钮：取消（默认）/ 重新加载 / 覆盖写入（danger 软底）。
  - 默认安全动作是取消。
- 与接入抽屉并发：
  - AgentSwitch 内部对 `~/.claude/settings.json` 的写入串行化（同一进程互斥）；
  - 设置区在保存前重新读取并比对；接入应用后设置区刷新文件内容与合并预览；
  - 设置区有未保存修改时，接入应用被阻断，只提供「去保存设置 / 取消」，不允许直接覆盖；
  - 接入有未保存修改时，设置保存仍可进行（只改非受管键）；下次应用接入再更新受管键；
  - 外部编辑器修改导致冲突时，走上方冲突对话框，不静默覆盖。

### 6.12 键盘与可访问性

- 所有层级/视图页签用框架 Tabs，支持方向键、Home/End。
- 所有表单标签与控件关联；错误通过 `aria-describedby` 关联。
- 焦点环使用主题 `Focus`；禁用控件仍可被读屏识别原因。
- 对话框 Esc 关闭（等价取消）；打开时焦点进入安全动作；关闭后焦点回到触发按钮。
- 颜色不是唯一信息载体：来源/状态/合并方式都有文本标签。
- 字号随系统 `TextScale`；标签列最小宽度 112，输入用 Grow，不写死像素。
- 复制、保存成功用 Toast；需要用户处理的错误用持久内联条，不被下一帧覆盖。

### 6.13 同页联动与跨页跳转

- 设置区受管键行 → 打开同页接入抽屉。
- 设置区「model 与网关不一致」提示 → 逻辑模型页（查看/登记模型）。
- 接入抽屉应用完成 → 设置区刷新受管键、继承区、合并预览。
- 接入摘要卡「待应用」→ 打开抽屉或直接应用。
- 设置区项目选择器 → 若项目有 `.mcp.json`，MCP 分组可显示服务器名，但不编辑文件。
- 设置区「受管键缺失」→ 打开接入抽屉重新应用。
- 切换 Agent 页签 → 关闭接入抽屉，保留 Claude Code 的未保存草稿；切回时恢复。

### 7.2 UI 表达规则

1. **禁用而不是隐藏**：用户需要知道「这个键存在，但这一层不能改」。只有在当前层完全无关的 Global config 键才隐藏。
2. **禁用必须给原因**：hover/行内文本说明「仅用户级可写」「不能写入项目共享」「仅托管策略可设置」「项目级不生效」。
3. **已有违规键不静默删除**：显示 warning 行 + 原值；保存时若本次未改动则原样保留；若本次改动则阻断并给出修复建议。
4. **scope 校验分层**：
   - 表单：违规键不出可编辑控件；
   - JSON：保存前校验，区分「本次修改引入」与「历史遗留」；
   - 合并预览：显示该键「被忽略/不生效」的来源标注。
5. **受管键在所有层都只读**：项目级出现受管键时额外警告「项目级覆盖会绕过 AgentSwitch 接入，可能导致网关鉴权/路由异常」。
6. **scope 规则可查**：页面提供「作用域规则」弹层，展示矩阵的简化版；不要求用户记住 30 个键。
7. **OR 合并单独表达**：`skipDangerousModePermissionPrompt` 不使用「最高层覆盖」；合并预览固定标注「任一层 true 即 true」，并展示各层 `true/false` 贡献。
8. **Skill 锁定不可绕过**：插件来源、托管策略、flag 或作者锁定 Skill 时，控件禁用并显示锁定原因；不允许 UI 写出 Claude Code 会忽略的覆盖值。

## 8. 受管键与同页接入边界（详细）

### 8.1 受管键定义

**合并后的建议（需产品确认）**：受管范围不再是原独立页时代的三个键，而是 **接入抽屉实际写入的全部键**。否则同一页会出现「接入抽屉写 `ANTHROPIC_DEFAULT_*`、设置区又能改同一个键」的双编辑器冲突。

| 组 | 键 | 由谁写 | 设置区行为 |
|---|---|---|---|
| 核心三键 | `env.ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_MODEL` | 接入抽屉「保存并应用」 | 常显只读；令牌默认遮蔽；`ANTHROPIC_MODEL` 保留 `[1M]` 后缀 |
| 快速模型 | `env.ANTHROPIC_SMALL_FAST_MODEL` | 接入抽屉 | 折叠在「接入投影」组内只读 |
| 角色映射 | `env.ANTHROPIC_DEFAULT_{SONNET,OPUS,FABLE,HAIKU}_MODEL` 与 `_NAME` | 接入抽屉 | 折叠只读 |
| 子代理 | `env.CLAUDE_CODE_SUBAGENT_MODEL` | 接入抽屉 | 折叠只读 |

当前原型展示 13 个键；实现时以接入代码实际写入的键集合为准，并让这个集合可被测试钉死。

### 8.2 边界规则

1. 接入抽屉保存并应用时**只新增/修改/删除受管键**；不清除设置区写入的其他键。
2. 设置区保存时**不得新增、删除、修改**任何受管键；即使它们出现在表单/JSON 中，也按原值写回。
3. 设置区不提供「一键应用接入」；受管键行提供「打开接入」，在同一页打开右侧抽屉。
4. 接入抽屉不编辑完整 settings；不展示权限、状态栏、项目配置。需要这些时关闭抽屉，在下方设置区编辑。
5. 两边都必须在写入前备份、原子写、检测外部修改；AgentSwitch 内部写入同一文件时串行化。
6. 受管键缺失时：
   - 设置区显示 warn「受管键缺失，接入可能未应用」+「打开接入」；
   - 不自动补齐，不猜测网关地址/令牌。
7. `ANTHROPIC_MODEL` 的 `[1M]`：
   - 设置区只读展示完整值（如 `my-code[1M]`）；
   - 显示「1M 上下文声明」徽章；
   - 不提供去掉/添加后缀的操作；如需改，打开接入抽屉勾选。
8. `model` 键（不是 `ANTHROPIC_MODEL`）由设置区管理，但必须提示与网关模型的关系：
   - 若接入已应用且 `model` 与受管 `ANTHROPIC_MODEL` 的基名不一致，保存确认框提示「可能导致网关 404」；
   - 提供「跟随网关」快捷值；
   - 不强制锁定，避免用户无法用 Claude Code 原生别名。
9. 接入应用与设置保存的互斥：
   - 设置区 dirty → 接入应用阻断，提供「去保存设置 / 取消」；
   - 接入 pending → 设置保存仍可进行，只改非受管键；应用接入时再更新受管键。
10. 接入应用后设置区刷新：
    - 用户级表单的受管行立即显示新值；
    - 项目级继承区与合并预览刷新；
    - JSON 视图的干净草稿重新加载为最新文档；
    - 设置区文件状态显示「已保存」，上次保存时间更新为应用时间。

### 8.3 需要向用户解释的文案

- 接入摘要卡/抽屉：「这里只写受管键（网关地址、令牌、模型与角色映射）；权限、状态栏、项目配置在下方「Claude Code 设置」中编辑。」
- 设置区受管键行：「接入投影键由上方接入管理，设置区只读。点「打开接入」修改。」
- 设置区缺少受管键：「受管键不完整，接入可能未应用。打开接入重新应用。」
- 设置 dirty 时应用接入：「设置还有未保存修改。先保存或放弃设置，再应用接入；应用接入只改受管键。」
- 冲突时：「接入刚刚更新了此文件。重新加载会丢失你当前的修改；覆盖写入会覆盖接入的更新。」

## 9. 数据、读取与写入需求（产品级）

### 9.1 读取

| 数据 | 来源 | 失败处理 |
|---|---|---|
| 用户级 settings | `~/.claude/settings.json` | 不存在=空态；解析失败=只读错误态 |
| 项目共享 | `<项目>/.claude/settings.json` | 同上 |
| 项目本地 | 解析后的 Git 仓库根 `.claude/settings.local.json` | 同上；路径解析失败时回退到项目目录并提示 |
| 项目列表 | `~/.claude.json` 的 `projects` | 读取失败=项目列表空态+手动选择仍可用 |
| 项目最近使用 | `~/.claude/projects/<encoded>/<lastSessionId>.jsonl` mtime → 项目目录 mtime → 名称 | 取不到就按名称，不阻塞 |
| 企业托管 | 标准 managed-settings 路径、drop-in、MDM/注册表（能读到的） | 不可读=标「不可见」，不阻塞 |
| 插件清单 | 本地插件注册信息 | 读取失败=只显示 `enabledPlugins` 中的项，标「安装状态未知」 |
| Skills 清单 | 用户/项目 `skills/*/SKILL.md`、已安装插件、内置技能清单、现有 `skillOverrides` | 读取失败=显示错误并保留已有 override，JSON 视图兜底；不冒充空列表 |
| MCP 服务器名 | 项目 `.mcp.json`（只读解析） | 失败=仅允许手动输入服务器名 |
| 网关模型 | AgentSwitch 逻辑模型列表 | 失败=不显示「跟随网关」建议，不阻断 |
| 备份列表 | `~/.agentswitch/backups/claude-settings/` | 失败=保存前备份仍必须成功，否则取消写入 |

### 9.2 写入

- 允许写入的路径只有：用户级 settings、所选项目的共享 settings、解析后的本地 settings。
- 禁止写入：Managed 文件、`~/.claude.json`、`.mcp.json`、插件目录、`--settings` 文件。
- 写入职责：接入应用只写用户级 settings 的受管键；设置保存只写当前层的非受管键。两者共用备份、原子写、冲突检测与串行化。
- 接入应用前必须确认设置区没有未保存修改；设置区 dirty 时阻断应用，不直接覆盖。
- 写入前必须：
  1. 重新读取并比对；
  2. 备份成功；
  3. 校验 JSON/scope/受管键；
  4. 计算 patch。
- 写入必须原子；失败时保留原文件，错误说明原因与下一步。
- 新文件权限 0600；已有文件保留原 mode；若检测到 group/world 可读且包含疑似密钥，显示安全警告（不强制改写权限）。
- 符号链接：写入真实目标，不替换链接；UI 显示真实路径。
- 不自动创建 `.claude` 之外的目录；创建 `.claude` 需用户确认。
- 不自动修改 `.gitignore`；项目本地文件未被忽略时提示「可能被提交」。

### 9.3 日志与遥测

- 不记录 settings 值、令牌、Authorization、Cookie、完整命令输出。
- 只记录脱敏元数据：文件层级、键路径、变更键数量、成功/失败、错误类别、耗时。
- 事件中不得出现完整路径中的用户名？路径可记录（用于排障），但不得包含密钥。
- 备份文件名不含密钥；备份内容本身是完整文件，需 0600。

## 11. 风险与待确认项

### 11.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| Claude Code 版本升级导致键类型/scope 变化 | 表单校验或 scope 规则过时 | 键注册表 + 版本号展示 + 升级复核；未知键走 JSON 并提示 |
| 合并预览与 Claude Code 实际行为不一致 | 用户误判生效值 | 明确标注 `--settings`/托管不可见；特殊规则（项目级 auto/bypass、autoMemoryDirectory）单独提示；以 Claude Code 实际运行为准 |
| 项目本地路径解析例外（Windows/非 Git/家目录仓库） | 写错文件 | 始终显示实际解析路径；解析失败回退并提示；不猜路径 |
| 接入抽屉与设置区并发写同一文件 | 覆盖用户修改 | 进程内互斥 + 保存前重读比对 + 应用前脏检查 + 冲突对话框 |
| JSON 视图暴露明文密钥 | 截图/分享泄露 | 表单/预览默认遮蔽；JSON 顶部警告；日志脱敏；项目共享密钥警告 |
| 危险模式确认默认 true 削弱安全提示 | 用户在 Bypass 模式下不再被确认框拦截 | 明确标注「预授权」语义与「默认开启」；提供关闭入口；不自动开启 Bypass；文档与 UI 双重提示 |
| Skills 清单读取不全或版本差异 | 用户看不到某个 Skill，或行状态与 `/skills` 不一致 | 明确来源与读取时间；识别失败不冒充空列表；未知 override 保留；以 Claude Code `/skills` 为最终参照 |
| 插件 Skill 被误认为可单独关闭 | 用户设置 `skillOverrides` 但无效 | 插件来源行禁用控件并显示「由插件管理」，只提供插件开关入口；不写无效 override |
| Skills 多层优先级与 Claude Code 实际不一致 | 有效状态判断错误 | 键注册表记录 local > project > user 与 policy/flag 锁定；显示来源而非只给结论；升级后复核 |
| 项目共享文件被提交 | 密钥进入 Git | 密钥检测 + 警告 + 建议改存本地；不自动改 `.gitignore` |
| 热加载判断错误 | 用户以为已生效 | 保守判断；未知键提示下次启动；文案「如未生效请重启」 |
| 大文件/复杂 JSON 卡顿 | 页面不可用 | 1 MiB 上限；JSON 解析防抖；必要时只读 |
| 托管策略来源读不全 | 预览不完整 | 标注「不可见」；不假装完整；提供原始 JSON（能读到的部分） |
| 接入抽屉可发现性不足 | 用户找不到模型/角色映射 | 摘要卡常驻「编辑接入」；状态徽章提示待应用/未保存；首次进入可展开一次 |
| 同页两个工作区仍可能被忽略 | 用户只改设置、忘了应用接入 | 摘要卡始终可见；待应用/未保存状态用 warn 徽章；设置区受管键行提供「打开接入」 |
| 未来 Codex 配置扩展 | 导航命名返工 | 本期唯一入口叫「Agent 接入」；未来在 Codex 页签内加设置，不改侧栏 |

### 11.2 待确认项（需要用户拍板）

1. **受管范围是否按合并方案扩大？** 合并后原型把接入实际写入的 13 个键（核心三键 + SMALL_FAST + 角色映射 + SUBAGENT）都设为设置区只读。这是对原「只锁三键」决策的修订；若坚持只锁三键，就必须接受同一页两个编辑器写同一键，或把角色映射移出设置区。建议按 13 键只读。
2. **`model` 与受管 `ANTHROPIC_MODEL` 冲突时怎么处理？** 当前方案是「可编辑 + 风险提示 + 跟随网关快捷值」，不锁定。若希望更安全，可在接入已应用时将 `model` 置为只读或默认隐藏。
3. **合并页面的命名。** 当前用「Agent 接入」作为唯一入口；是否改为「Agent 接入与配置」更直白？未来 Codex 设置仍留在 Codex 页签，不再新增侧栏项。
4. **企业托管来源的展示范围。** 是否要求读取 MDM plist / Windows 注册表 / 远程组织策略？部分来源 AgentSwitch 无法可靠读取，只能标注「不可见」。需要明确「只展示可读文件」还是「必须展示所有来源及不可见状态」。
5. **JSON 视图的密钥显示策略。** 当前建议：表单/预览默认遮蔽，JSON 显示明文并强警告。是否要求 JSON 也默认遮蔽（会降低高级用户编辑效率）？
6. **项目本地文件是否自动加入 `.gitignore`。** 当前建议只提示、不自动改。若希望自动，需要明确边界（只在新建文件时？只改项目根 `.gitignore`？）。
7. **「撤销本次保存」是否 P0。** 当前列为 P1。若用户经常手滑，建议 P0 提供「从最近备份恢复」。
8. **scope 键注册表的维护责任。** 需要明确谁在 Claude Code 升级后更新 30 键/4 键/12 Global 键清单，以及是否在 UI 显示「规则基于 Claude Code x.y」。

## 12. 原型说明

原型文件：`docs/prototypes/claude-code-config-page.html`（单文件、内联 CSS/JS、假数据）。

可直接演示：

1. 侧栏只有一个「Agent 接入」入口；默认 Claude Code 页签，顶部可见 Agent 页签与接入摘要卡。
2. 点「编辑接入」打开右侧抽屉；修改默认模型、1M、角色映射，观察受管键预览即时更新。
3. 关闭抽屉，摘要卡显示「有未保存的接入更改」；点「应用接入」走确认框，应用后设置区受管键刷新。
4. 打开抽屉点「仅保存」，摘要卡变「待应用」；再点摘要卡「应用接入」完成应用。
5. 设置区有未保存修改时点「应用接入」，会弹「先处理未保存的 Claude Code 设置」，只提供「去保存设置 / 取消」。
6. 停掉左下角网关，摘要卡显示「网关已停止」，应用按钮禁用；重新启动后恢复。
7. 设置区切换用户级 / 项目级 / 企业托管；项目级选择项目（含 Git 子目录示例），切换共享/本地。
8. 表单编辑 `model`、`fallbackModel`、环境变量、权限（含「危险模式确认」，用户级默认开启）、状态栏、插件开关；在「Skills」卡片切换某个用户 Skill 的开启/关闭，观察计数与合并预览变化；插件来源的 Skill 显示为锁定。
9. 展开「接入投影的其他 N 个键」查看全部只读受管键。
10. JSON 视图编辑；制造语法错误看行列提示；加入 `modelPicker` 到项目文件看 scope 阻断；修改任一接入投影键看阻断。
11. 合并预览：每个键的来源文件、数组并集、权限求值顺序、整值替换例外；`skipDangerousModePermissionPrompt` 显示「任一层 true」及各层贡献；`skillOverrides.<name>` 显示逐键状态与来源。
12. 保存设置：确认框显示路径/变更键/备份/生效范围；保存后显示「已热生效 / 需重启 / 下次启动」。
13. 脏状态切换：修改设置后切层级/项目，弹「继续编辑 / 放弃修改」；切 Agent 页签保留 Claude 草稿。
14. 企业托管：只读来源与最终策略，无编辑控件。
15. 「作用域规则」弹层：scope 矩阵简化版。

原型中的路径、项目、插件、Skills、MCP 服务器、托管策略均为假数据；不连接后端，不写入任何文件。

## 附录 B：需求决策记录（供评审）

| 决策 | 结论 | 理由 |
|---|---|---|
| 页面形态 | 单一「Agent 接入」入口；Claude 页签内「接入摘要卡 + 抽屉 + 设置区」 | 用户反馈两页来回切换成本高；同一文件的两类写入放在同一上下文 |
| 导航名 | 「Agent 接入」单一入口 | 合并接入与设置，避免两个入口；未来 Codex 设置留在 Codex 页签 |
| 项目级文件形态 | 共享 + 本地两个子页签 | 两者语义不同（提交 vs 本地），不能混为一个编辑器 |
| 托管呈现 | 独立只读层级 | 用户需要知道策略限制，但不能误以为可编辑 |
