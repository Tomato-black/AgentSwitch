## 2. 关键决策详情

### PD-1：定位为「本地 AI Agent 的可靠性层」

**决策**：对外一句话从「模型 API 网关」进一步收敛为「本地 AI Agent 的可靠性层」：

> 让 Claude Code / Codex / Claude Desktop 永远指向一个本地入口；按逻辑模型在多个供应商/模型之间做可解释的故障转移；单二进制、零云依赖、密钥本地加密。

**依据**：
- CC Switch 已从配置切换器扩展到本地 Routing/Aggregation、用量、配额、MCP/Skills、云同步、12 工具；「另一个配置管理器」没有胜算。
- CCR/9Router 证明「本地网关 + 自动 fallback」有真实需求，但也暴露了路由配置脆弱、协议兼容、熔断状态等痛点。
- AgentSwitch 的独特组合是「逻辑模型目标链 + 三入站协议 + 本地隐私 + 单二进制」，不是「渠道数量」。

**影响**：
- 功能取舍：优先「可解释/可恢复/可迁移」，而不是「更多 Agent/更多预置/更多模式」。
- 文案与 UI：第一屏要能解释「逻辑模型在做什么」，而不是只展示渠道列表。
- 增长：面向「已经被上游故障/额度折腾过」的用户，而不是「想管理 12 个工具」的用户。

**信心**：高。**复议条件**：用户明确要做团队/服务端网关或全球 12 工具管理器。

---

### PD-2：先修保存/应用/备份语义（P0-0）

**决策**：在开发任何新功能前，先修复「仅保存」对当前已应用配置直接改写 live 且不备份的问题；拆分「落库」与「投影」，任何 live 写入前先备份，列表显示「待应用/已应用/文件已过期」。

**依据**：
- `AccessConfigs.Update` → `RegenerateDerived` 会对 current 配置执行 `writeClaudeLive`/`writeCodexLive`，不调用 `backupLive`（`internal/bridge/access_configs.go:101-128,258-300`）。
- `backupLive` 只在 `Apply`/`RestoreLatestBackup` 调用（`internal/bridge/access_live.go:173-260`）。
- UI 的「仅保存」入口在 `internal/desktop/accesskit/editor.go:85-96,163-223`；临时测试实测仅保存后 live 出现新键、备份数不变。
- README 承诺「写入前备份」；这条路径与承诺不符。

**影响**：
- 接入页「保存并应用/仅保存」语义、备份策略、列表状态、测试。
- 这是**现有缺陷**，不是新功能；不占 P0 功能名额，但必须最先修。

**信心**：高（代码 + 临时测试）。**验收**：编辑 current → 仅保存 → live 字节不变；保存并应用 → 最新备份内容等于保存前 live。

### PD-3：可观测性列为 P0

**决策**：把「请求/路由历史持久化 + 诊断导出」作为 P0。

**依据**：
- 当前只有 20 条 UI 请求 + 100 条内存环；重启清零；无筛选/导出（`internal/telemetry/ring.go`、`pages/settings/settings.go`）。
- 竞品普遍有请求日志/用量/trace；CC Switch、CCR、LiteLLM、new-api、9Router 均有。
- 故障转移是核心卖点；如果用户看不到「候选过滤、冷却、跳过原因、耗时」，就无法验证它是否工作。

**影响**：新增 SQLite 表/migration、gateway 写入路径、bridge 查询、UI 历史视图；必须设计脱敏/保留/磁盘上限；不能记录 prompt/response 正文。

**信心**：高。**验证**：5 名用户完成「模拟 429 排障」，记录是否能在应用内找到原因。

---

### PD-4：端到端测试/接入验证列为 P0

**决策**：在逻辑模型/接入流程提供最小「测试请求」能力：按目标链发一条最小请求，显示每个目标的成功/失败、耗时、命中目标；失败给「下一步」。

**依据**：
- 渠道详情只有「测试连通」，不测逻辑模型/目标链/接入（`internal/bridge/channels.go:174-195`）。
- 逻辑模型页无测试入口；首次接入没有闭环。
- 竞品有 CCR 协议探测、new-api Playground、LiteLLM health；CC Switch 连通性检查只测可达性。

**影响**：复用 provider 探测；需要费用提示；测试不应污染生产冷却/统计（或单独标记）。

**信心**：高。**验收**：选择逻辑模型发测试请求，显示状态/耗时/命中目标；失败显示下一步；不泄露密钥；有费用提示。

### PD-5：配置导出/导入放 P1（对 PM 建议的调整）

**背景**：PM 建议把配置导出/导入/迁移列为 P0，理由是「配置是资产；无迁移=锁定；换机/重装流失」。主 Agent 评估后调整为 P1。

**决策**：P0 只保留「写入一致性 + 历史/解释 + 端到端测试 + E2E/平台门禁」；配置导出/导入/备份列表放 P1，与 PD-7 同批。

**理由**：
1. P0 已经包含一个缺陷修复 + 两个中等偏大的功能 + 发布门禁；再加入导出/导入会拉长「可信闭环」的交付时间。
2. 导出/导入不阻塞日常使用；当前用户规模还没有形成「大量换机/迁移」的强需求。
3. 但备份语义（PD-2/PD-7）必须在 P0 修，否则导出/导入会建立在错误的保存语义上。
4. 如果用户认为迁移是当前增长瓶颈，可以把 PD-5 上调回 P0。

**状态**：**待拍板**（Q3）。

---

### PD-6：用量/成本做「估算」，不做账单级

**决策**：
1. 做 token/请求/按渠道/模型/时间的用量统计；
2. 成本用「可编辑价格表 + 估算」，明确标注不是账单；
3. **建议推翻** 2026-10-17 spec 中「不做用量/配额统计页」的非目标；
4. 不做供应商余额自动抓取（P2 再评估）。

**依据**：
- 竞品基础能力：CC Switch usage/heatmap/custom pricing；CCR token/cost；9Router 配额窗口/成本估算；LiteLLM spend tracking；new-api usage logs。
- 订阅套餐（Coding Plan）不是按 token 线性计价，美元成本没有唯一真相；9Router 也明确「成本只是估算」。
- AgentSwitch 的预置包含 6 家 Coding Plan；用户更需要「用了多少/还剩多少」，而不是「账单金额」。

**影响**：需要从三种协议/流式响应提取 usage；新增 usage 表；价格表维护。产品文案必须克制：不能承诺「账单级准确」。

**信心**：中高。**需用户拍板**：这是对旧 spec 非目标的明示推翻（Q1）。

---

### PD-7：备份升级为「历史列表 + 选择恢复」

**决策**：把现有「每 Agent 最近 10 份、仅还原最近一份」升级为：
- 备份列表（时间、Agent、配置名、大小、触发原因）；
- 选择任意一份恢复；
- 恢复前自动快照当前状态；
- 支持导出单份备份；
- 清理策略（按数量/天数）。

**依据**：`access_live.go:180-260` 备份文件名含时间戳，但 UI 只暴露「还原最近备份」；用户改坏后无法回到更早版本；竞品有备份列表/项目。

**影响**：备份元数据/UI；与 PD-2 同批设计，避免「备份拍到新状态」。

**信心**：高。**验收**：无备份按钮禁用；有备份显示时间；可选择任意备份恢复；恢复前自动快照。

---

### PD-8：多账号先做「渠道复制 + 主备链模板」

**决策**：先做轻量替代：复制渠道（保留 base URL/协议/模型建议，默认不复制 Key），一键加入现有逻辑模型目标链；完整密钥池等证据（>30% 目标用户需要）再评估。

**依据**：
- 当前单 Key/渠道；`channel_keys` 多密钥表已于 2026-10-17 重构删除。
- 竞品普遍多账号/凭证池，但 AgentSwitch 的目标用户规模与 schema 成本不匹配。
- 重复渠道 + 目标链可以表达「主 Key + 备 Key」。

**影响**：渠道页/逻辑模型页；不涉及 schema。完整密钥池需要新 migration + 兼容测试。

**信心**：中。**需用户确认需求强度**（Q4）。

### PD-10 ~ PD-18 摘要

- **PD-10**：OAuth 订阅登录暂不做；服务授权渠道/API Key，避免条款与凭据风险。
- **PD-11**：更多 Agent 按需求逐个添加；每个都要接入/应用/还原/E2E；不追 12+。
- **PD-12**：真实 Agent E2E + Windows/macOS ARM 实机作为发布门禁；无实机不宣称支持。
- **PD-13**：文档只写可验证事实；修正 `qa-report` 的 `TestAppMenuShortcuts` 不实声明与「应用菜单已完成」不实记录；同步 README/ARCHITECTURE。
- **PD-14**：告警先做应用内/托盘；MyGo v0.6.2 支持 `NewNotification`/`OnNotificationClick`，但需实机验证后再承诺系统通知。

- **PD-18**：请求历史默认保留 **7 天**（2026-10-29 用户决定；暂不提供配置），仅元数据，不存 prompt/response 正文。

| 做云同步 | CC Switch/9Router | 与本地优先/零云冲突；用加密导出/导入替代 |
| 做 12+ Agent 全覆盖 | CC Switch | 维护成本线性；先保 Claude/Codex 真实稳定；按需求逐个加 |
| 做免费层套利/OAuth 订阅登录 | 9Router/CC Switch | 条款/稳定性/安全默认风险高；与「可靠/隐私」定位冲突 |
| 做 CLI/无头模式 | CCR/LiteLLM | 与桌面优先定位冲突；明确团队/服务器需求再评估 |
| 做批量操作/拖拽排序 | new-api/CC Switch | 当前规模收益低、误操作风险；先搜索/状态（PD-16） |

## 6. 一句话建议

**先把「可靠」做成可验证的事实：修复保存/应用/备份语义，持久化请求/路由历史，提供端到端测试与真实 Agent 回归；再谈用量、告警、多账号、更多 Agent。不要为了追上 CC Switch 的功能清单，把 AgentSwitch 做成一个更脆弱的配置管理器。**
