## 3. 下一步建议（排序方法：prioritize-features 技能，ICE 加权）

> 评分口径：Impact 1–5（5=全体用户可感知的核心信任/流程改善）；Confidence 0.5–1.0（无用户证据 ≤0.8，已验证事实 1.0）；Ease 1–5（5≈≤1 天，1≈>1 月）。ICE = I × C × E。

### 3.1 判断：v0.2.1 该不该发

**结论：该发，且应尽快发，但发前有三件必做事项。**

理由：
1. 尾款批 A–E 已全部落地且 `-race` 全绿（尾款计划「执行记录」；git log 2026-11-08 共 13 个提交），修复的都是 v0.2.0 用户可直接感知的缺口（重启后历史为空、半开不可见、导出无加密、额度无告警）——压着不发，用户在 0.2.0 上持续承受这些已知问题。
2. 人工验收欠账（V-1..V-7）**不构成阻塞**：项目已有「诚实标注」先例（README Windows 标 🚧 待实机验证；v0.2.0 即在 smoke 未跑的情况下发布并如实说明），符合 PD-13「文档只写可验证事实」。发版说明里明列「未验证项」即可。
3. 但 §2.1 的文档回写**必须先于发版**：roadmap 明细与代码事实相反是「文档撒谎」，带着它发版违背本项目最重视的 PD-13。

**发前必做（约 0.5 天）**：
1. 执行 F2 全部：roadmap 明细回写、CLAUDE.md 记录尾款批、qa-report 增补；顺带 D-4（提交执行记录）、D-5/D-6/D-7 的最小修订（capability-matrix 加 2026-11-08 状态注、decisions 状态刷新、backlog 加完成标记）。
2. `mygo.json` → 0.2.1；三平台打包；README/官网/手册版本更新。
3. GitHub Release（notes 含「Windows 实机/真实 smoke/用量对照未验证」的诚实声明）+ Gitee 网页手动创建。

**发后一周内强烈建议**：跑一次真实 Agent smoke（约 30 分钟、消耗少量额度）——它是历史/诊断/告警这批 v0.2.1 核心交付的唯一端到端验证。
