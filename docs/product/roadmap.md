# AgentSwitch 下一阶段产品路线图（2026-10-29）

> 配套：`competitive-analysis.md`、`capability-matrix.md`、`feature-gap-analysis.md`、`feature-backlog.md`、`decisions.md`。
> 本文不承诺具体工期；复杂度为相对量级（S/M/L/XL），依据见每项。路线图以「用户可感知结果」和「可验收」为单位，不以「代码写完」为单位。

---

## 0. 路线图原则

1. **先修复信任，再扩展能力**：保存/应用/备份语义、静默失败、状态真实性是底线；不先修，新增功能会放大误导。
2. **先把「可靠」变成可验证的事实**：故障转移是核心卖点；没有持久化历史、端到端测试、真实 Agent 回归，就无法证明它工作。
3. **先补定位需要的能力，再补竞品有的能力**：不把 cc-switch 的 12 工具/90+ 预置/MCP 当 KPI。
4. **不引入与定位冲突的架构**：不做云同步、多租户、Node/Python/Redis、条件路由 DSL、插件系统。
5. **真实 Agent 兼容性与平台实机验证是发布门禁**，不是测试项。

## 1. P0：可信闭环（下一个发布范围）

### 1.1 为什么现在做

- 当前存在一个会直接破坏信任的写入一致性缺陷：对已应用配置点「仅保存」会改写 Agent live 文件且不备份（见 `feature-gap-analysis.md` A0）。不修，用户不敢试错，「写前备份」承诺不成立。
- 故障转移是核心卖点，但只有 20 条内存请求；用户无法回答「刚才为什么切、切到哪、冷却到几点」。
- 首次接入没有端到端验证；用户配置完不知道是否真的通。
- 离线测试通过不等于真实 Claude Code/Codex 可用；Windows/macOS ARM 未实机，发布宣称与事实不符。

### 1.2 P0 范围

| ID | 交付物 | 用户可感知结果 | 复杂度 | 依赖 | 验收标准 | 不做的代价 |
|---|---|---|---|---|---|---|
| **P0-0** | **保存/应用/备份语义修复** | 「仅保存」真的只保存；「应用」才改 Agent 文件；任何 live 写入前有备份；列表显示「待应用/已应用/文件已过期」 | **S–M**：拆分落库与投影、备份前置、状态字段/徽章、测试 | `internal/bridge/access_*`、`accesskit/editor.go`、接入页 | 1) 编辑 current → 仅保存 → live 字节不变；2) 保存并应用 → 最新备份内容等于保存前 live；3) 全局配置保存同样走备份；4) 列表显示待应用/已应用/过期；5) 自动化覆盖两条路径；6) 文档与 README 承诺一致 | 用户以为已保存/已备份，实际没有；一次误操作就可能丢掉可回滚状态；核心信任受损 |
| **P0-1** | **请求/路由历史持久化 + 故障解释 + 诊断导出** | 重启后仍能查最近请求；能展开尝试链、筛选、导出诊断包 | **M–L**：SQLite 表/迁移、gateway 写入路径、UI 历史视图、保留/清理；不能阻塞热路径 | `internal/telemetry`、`internal/gateway`、`internal/storage`、`internal/bridge`、设置页 | 1) 持久化脱敏元数据，默认保留 7 天（2026-10-29 用户决定；暂不提供配置）；2) 按状态/模型/渠道/时间筛选；3) 尝试链含渠道/模型/跳过原因/耗时/上游状态；4) 导出 JSON/CSV + 脱敏诊断包；5) **不存 prompt/response 正文**；6) 重启后历史仍在；7) `go test ./...` + 关键并发 `-race` 通过 | 用户无法回答「刚才为什么切了」；故障转移信任无法建立；支持成本高 |
| **P0-2** | **端到端测试 / 接入验证 + 错误「下一步」** | 配置后一键发测试请求，看到每个目标的成功/失败/耗时/命中目标；失败时知道下一步 | **S–M**：复用 provider 探测、最小请求、错误文案映射、费用提示 | `internal/provider`、`internal/gateway`、`internal/bridge`、逻辑模型页/接入页 | 1) 选择逻辑模型发一条测试请求，显示状态/耗时/命中目标；2) 明确提示可能产生少量费用；3) Top 5 错误（401/403/404/429/5xx/全冷却）带「下一步」；4) 失败保留机器可读 type；5) 不泄露密钥；6) 不污染生产冷却/统计（或单独标记）；7) Fake Provider 覆盖成功/失败 | 首次上手断在「配置完不知道通不通」；用户无法区分 Key、模型名、协议、冷却、接入文件问题 |

### 1.3 P0 验收门禁

- 自动：`go build ./...`、`go vet ./...`、`go test ./...`、`go test -race ./...`（并发/冷却/历史写入相关）。
- 手动：真实 Agent smoke（Claude Code/Codex）；备份/恢复演练；导出文件安全审查；Windows/macOS ARM 实机。
- 用户：5 名目标用户完成「模拟 429 排障」「改坏配置后回滚」「首次接入并验证」三项任务，记录完成率/时间/卡点。
- 文档：README/ARCHITECTURE/qa-report 与实现一致；不再出现未实现功能/不存在的测试名。

### 1.4 P0 不做什么

- 不做完整密钥池、条件路由、会话粘性、更多 Agent、云同步、自动更新。
- 不做账单级成本、供应商余额抓取；P0 只做请求/路由历史与最小验证。
- 不做配置导出/导入（放 P1；但 P0-0 的备份语义必须先修，避免导出/导入建立在错误的保存语义上）。

## 2. P1：可靠性的可见化与规模化

### 2.1 为什么在 P0 之后

- P0 建立了「写入可信 + 历史可解释 + 接入可验证」的地基；P1 才能基于真实数据做用量、告警、搜索、迁移。
- 没有 P0 的持久化，P1 的用量/告警会重复返工。

### 2.2 P1 范围

| ID | 交付物 | 用户可感知结果 | 复杂度 | 依赖 | 验收标准 | 不做的代价 |
|---|---|---|---|---|---|---|
| **P1-1** | **备份列表 + 配置导出/导入/迁移** | 备份可选时间恢复；一键导出全部配置；新机导入后 Claude Code/Codex 可用 | **M**：版本化导出格式、导入校验/预览、密钥策略、备份元数据；不破坏 schema | P0-0、`internal/storage`、`internal/bridge`、`internal/credential`、接入页/设置页 | 1) 备份列表显示时间/Agent/大小/触发原因；2) 可选择恢复；3) 恢复前自动快照；4) 导出含渠道/逻辑模型/接入配置/设置；5) 默认不含明文密钥；6) 可选密码加密导出；7) 导入前预览差异/冲突；8) 迁移演练 A→B 后各发一条请求成功；9) 导出文件无明文密钥（自动化） | 配置锁定；用户不敢试；换机/重装流失；备份安全网不完整 |

## 3. P2：扩展与探索（有证据再做）

### 3.1 为什么放后

- P2 收益不确定性高、维护成本高；只有在 P0/P1 建立信任并有明确用户证据后才投入。
- P2 的目的是「扩大边界」，不是「补齐竞品清单」。

### 3.2 P2 候选

| ID | 方向 | 触发条件 | 复杂度 | 验收标准 | 不做的代价 |
|---|---|---|---|---|---|
| P2-1 | 完整密钥池/轮询/额度感知 | P1-7 验证后仍有 >30% 目标用户需要；或用户明确要求 | **XL**：schema、凭据选择、冷却/轮询、UI、审计 | 同一渠道多 Key；轮询/优先级；额度耗尽自动切换；失败可解释；迁移兼容 | 多账号重度用户流失；但可通过多建渠道缓解 |
| P2-2 | 更多 Agent（Gemini CLI/OpenCode 等） | 目标用户请求量/访谈证据；配置格式稳定 | **M/每个**：配置投影、协议、E2E、文档 | 每个 Agent 有接入/应用/还原/E2E；不破坏现有三协议 | 获客面窄；但避免维护爆炸 |
| P2-3 | 会话粘性/亲和 | 用户反馈「切换导致缓存失效/会话异常」显著 | **L**：会话 ID 提取、粘性状态、TTL、故障语义 | 同会话优先同目标；故障时可切换；TTL/清理；可关闭 | 多目标切换体验差；非核心 |
| P2-4 | Provider 配额/余额探测 | 供应商提供稳定 API/条款允许；用户需求明确 | **L**：多供应商适配、认证、限流、错误处理 | 只读余额/配额；失败降级；默认关闭；不抓取网页 | 用户需手动查余额；但不影响核心 |
| P2-5 | 自动更新/检查更新 | 发布频率提升、签名/公证就绪 | **M–L**：签名、更新源、回滚、增量 | 检查更新 + 下载；可选自动；失败可回滚；不破坏离线 | 手动升级摩擦；安全修复延迟 |
| P2-6 | 国际化（英文） | 决定面向 S4 全球用户 | **M**：文案抽取、布局、字体、测试 | 英文 UI 完整；中文不回归；布局不裁切 | 全球获客受限；中文定位可接受 |
| P2-7 | CLI/无头模式 | 明确团队/服务器需求，且愿意重做定位 | **XL**：生命周期、配置、认证、日志、部署 | 无 GUI 启动/停止/配置/日志；与桌面共享核心 | 无法服务服务器用户；但与本地优先定位冲突 |
| P2-8 | 条件路由/请求改写 | 明确的「同一 Agent 内按任务分流」需求 | **L**：规则引擎、冲突/优先级、调试 UI | 至少 3 种规则；可解释；可关闭；不破坏简单路径 | 高级用户受限；但避免复杂度 |

### 3.3 P2 明确不做

- 云同步、MCP/Skills/Prompts、会话阅读、Token 压缩/RTK、多租户/虚拟 Key/计费、Guardrails/语义缓存、OAuth 订阅登录、12+ Agent 全覆盖、远程访问/移动端、插件系统。
- 理由见 `decisions.md` 与 `feature-backlog.md` §6。

## 4. 阶段依赖与顺序

```
P0-0 写入一致性/备份语义 ──┬──> P1-1 备份列表/导出导入
                          └──> B1 待应用状态

P0-1 历史/诊断 ──┬──> P1-2 用量/成本
                 ├──> P1-4 告警
                 ├──> P1-5 搜索/diff/日志
                 └──> P1-6 半开探测

P0-2 端到端测试 ──> P1-3 首次上手闭环

P1-1 导出/导入 ──> P1-8 从 cc-switch 导入
P1-7 渠道复制 ──> P2-1 完整密钥池（仅在有证据时）
P0-3 E2E/平台门禁 ──> 所有后续发布的质量前提
```

**关键路径**：P0-0（写入可信）→ P0-1（历史基础设施）→ P1-2/P1-4/P1-5/P1-6（基于历史的能力）。不要先做用量/告警再补历史。

## 5. 各阶段「暂不做的代价」

### P0 暂不做

- 用户仍可能被「仅保存」误导 → 一次误操作就丢掉可回滚状态；
- 故障转移不可解释 → 核心卖点不可验证；
- 首次接入无法验证 → 用户不知道是否真的通；
- 真实 Agent/平台未验证 → 一次协议回归或平台问题就可能摧毁口碑。

### P1 暂不做

- 配置不能迁移 → 用户不敢投入；换机/重装流失；
- 用户不知道消耗/额度 → 订阅用户无法规划，竞品差距扩大；
- 无告警 → 托盘驻留形态不可靠；
- 无搜索/引导 → 条目增长后可用性下降。

### P2 暂不做

- 获客面较窄、无法服务团队/服务器用户；
- 但这是有意识的取舍：优先把「单机可靠性层」做透，而不是变成功能更多但更脆弱的 cc-switch/LiteLLM 混合体。

## 6. 成功指标（建议）

> AgentSwitch 零遥测；以下指标优先通过本地/自愿反馈、用户测试、支持问题收集，不做暗上报。

| 阶段 | 指标 | 目标（假设） | 验证方式 |
|---|---|---|---|
| P0 | 「仅保存/应用/备份」语义正确性 | 100% 自动化覆盖 | 两条路径测试 |
| P0 | 「故障原因可在应用内定位」的比例 | ≥80% 的测试场景 | 5 名用户任务测试 |
| P0 | 首次接入后通过测试请求的比例 | ≥80% | 5 名用户任务测试 |
| P0 | 真实 Agent smoke 通过率 | 100% 发布阻断 | CI/手动清单 |
| P1 | 换机迁移时间 | 从 30+ 分钟降到 ≤5 分钟 | 迁移演练 |
| P1 | 导出文件明文密钥泄露 | 0 | 自动化扫描 |
| P1 | 用量 token 与供应商控制台误差 | <5% | 3 家对照 |
| P1 | 首次接入完成率（不读 README） | ≥80% | 5 名用户测试 |
| P1 | 告警误报/疲劳 | 可接受（用户可关闭，去重） | 用户反馈 |
| P1 | 搜索/筛选任务时间 | 降低 50% | 计时测试 |
| P2 | 新 Agent 的维护成本 | 每个 Agent 有 E2E，不破坏核心 | 发布检查 |
| P2 | 自动更新失败回滚 | 100% 可回滚 | 演练 |

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 历史/用量写入影响 gateway 热路径 | 请求延迟/稳定性 | 异步写入/批量写；有界队列；失败降级为丢弃并计数；`-race` 测试 |
| 用量/成本估算不准确 | 用户不信任 | 明确「估算」；显示数据来源/置信度；允许用户校准价格；不承诺账单 |
| 导出包含密钥导致泄露 | 安全事故 | 默认不含明文；加密导出；导出前扫描；文档警示 |
| 多账号/密钥池 schema 变更 | 迁移风险 | 先做渠道复制；完整池走新 migration + 兼容测试；不删库 |
| 更多 Agent 维护爆炸 | 质量下降 | 每个 Agent 独立子包 + E2E；按需求逐个加；不追 12 工具 |
| 平台验证资源不足 | Windows/ARM 口碑 | P0 门禁；无实机不宣称支持；README 标注状态 |
| 竞品快速迭代 | 差异化被稀释 | 守住「逻辑模型级故障转移 + 可解释 + 隐私 + 单二进制」；不追功能清单 |
| 用户不愿为可解释性付出配置成本 | 采用率低 | 默认简单路径；高级信息渐进披露；引导/模板 |
